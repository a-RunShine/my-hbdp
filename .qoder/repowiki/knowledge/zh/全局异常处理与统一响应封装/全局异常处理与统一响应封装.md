本仓库采用 Spring Boot 的 `@RestControllerAdvice` + `@ExceptionHandler` 模式实现全局异常捕获，并通过统一的 `Result` DTO 向客户端返回结构化错误信息。核心机制如下：

1. **全局异常处理器**：`WebExceptionAdvice` 使用 `@RestControllerAdvice` 注册，通过 `@ExceptionHandler(RuntimeException.class)` 拦截所有未处理的运行时异常，记录日志后统一返回 `Result.fail("服务器异常")`。
2. **统一响应体**：`Result` 提供 `ok()` / `ok(data)` / `ok(list, total)` / `fail(errorMsg)` 静态工厂方法，将成功/失败状态、数据、分页总数等字段标准化为 JSON 响应。
3. **业务异常抛出方式**：当前代码中业务层直接 `throw new RuntimeException(...)`（如文件上传失败、密码格式不正确、Redis 操作异常），由全局处理器兜底转换为 `Result.fail` 响应。
4. **缺失的设计点**：
   - 没有定义专门的业务异常类型（如 `BusinessException`）或错误码枚举，导致无法区分不同业务场景的错误；
   - 仅捕获 `RuntimeException`，对受检异常、参数校验异常（如 `MethodArgumentNotValidException`）、自定义 HTTP 状态码等无专门处理；
   - `Result` 缺少 `code` 字段，前端只能通过 `success` 布尔值判断成功与否，无法基于错误码做精细化处理。

开发者应遵循的约定：在 Service 层遇到可预期的业务错误时抛出 `RuntimeException`（建议后续升级为自定义异常类型），让全局处理器统一收敛；Controller 层不自行 try-catch 业务异常，保持调用链简洁。
